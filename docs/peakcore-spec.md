# PeakCore — легковесный монитор ресурсов в системном трее

Документ — спецификация и рабочий план разработки. Рассчитан на то, чтобы по нему можно было идти этап за этапом (самостоятельно или с агентом), не додумывая архитектуру.

**Допущение:** основная платформа — Windows 10/11. macOS/Linux — вне MVP.

---

## 1. Цель и принципы

Крошечное приложение, живущее в трее: постоянно следит за CPU и памятью, показывает текущие значения прямо на иконке, по клику открывает красивое окно-дашборд с рейтингом процессов и графиками.

Принципы:

1. **Демон крошечный.** Всё тяжёлое (UI, тяжёлый сбор по процессам) живёт в отдельном процессе, который существует только пока открыто окно.
2. **Метрика, ломающая бюджет, уезжает в «только при открытом окне».**
3. **Окно красивое.** Дизайн — часть продукта, а не «потом».
4. **Без прав администратора** в MVP.

### Бюджет ресурсов (ориентиры, подтверждать замерами в каждом этапе)

| Параметр | Цель |
|---|---|
| Демон в трее, окно закрыто: working set | ≤ 5–8 МБ |
| Демон: CPU в среднем | < 0.1 % |
| Демон: размер exe | ≤ 3 МБ |
| Окно открыто (UI + WebView2, суммарно) | допустимо до ~150–200 МБ, процесс умирает при закрытии |
| Окно: CPU при открытом дашборде, обновление 1 Гц | < 2–3 % одного ядра |
| Окно: CPU когда свёрнуто/скрыто | ≈ 0 % (обновления и анимации остановлены) |
| Запуск демона до появления иконки | < 100 мс |
| Открытие окна (первый кадр) | < 1 с |

## 2. Стек и обоснование

### Демон: Rust

Без рантайма и GC, статический бинарник, прямой доступ к Win32 через крейт `windows`.

- Трей и меню: `tray-icon` + `muda`.
- Метрики: собственные вызовы Win32 (быстрее и легче, чем универсальные библиотеки).
- Аргументы CLI: `lexopt` (а не `clap` — экономия размера).
- Конфиг: `toml` + `serde`.
- Без async-рантайма: Win32 message loop, таймер, один поток для pipe-сервера.

### Окно: Tauri v2 + Vue 3 + TypeScript

Раньше в черновике было egui. Для действительно современного, «дашбордного» вида веб-стек сильно удобнее: градиентные графики, плавные анимации, glass-карточки, нормальная типографика. Вес окна не критичен, потому что процесс окна живёт только пока оно открыто. Плюс это ваш родной стек (Vue/TS).

- Фронтенд: Vue 3 (Composition API), Vite, TypeScript, **Tailwind CSS** + CSS-переменные для токенов темы, Pinia для состояния.
- Графики: **uPlot** (очень лёгкий и быстрый для time-series, градиенты и кастомный рендер настраиваются) + собственные SVG-компоненты (радиальные «спидометры», спарклайны, тепловая карта ядер). ECharts — только если понадобится treemap, и подгружать лениво.
- Шрифты: Inter (variable, subset woff2, в комплекте приложения) + JetBrains Mono для PID/чисел; `font-variant-numeric: tabular-nums` везде, где меняются числа.
- Иконки: Lucide (tree-shaken).
- Эффекты окна: безрамочное окно, своя title bar; Mica на Windows 11 (крейт `window-vibrancy`), на Windows 10 — сплошной фон (acrylic лагает при перетаскивании).
- Окно запускает WebView2: на Windows 11 он есть, на Windows 10 ставится установщиком (bootstrapper).

### Что НЕ используем

Electron; Tauri как *постоянно живущий* процесс; тяжёлые графические библиотеки в демоне.

## 3. Архитектура

```
┌───────────────────────── peakcore.exe (демон, Rust) ─────────────────────────┐
│ Win32 message loop + таймеры (без busy-loop)                                  │
│  ├─ Sampler L1 (каждые 2 с): общий CPU %, RAM %                               │
│  ├─ History: ring buffer 1 ч (2 с) + минутные агрегаты 24 ч                   │
│  ├─ Tray: иконка с цифрами, tooltip, меню                                     │
│  ├─ Alerts: пороги и уведомления                                              │
│  └─ IPC-сервер: named pipe \\.\pipe\peakcore-<user-sid>                       │
└───────────────────────────────────────────────────────────────────────────────┘
        ▲ pipe                          ▲ pipe
┌───────┴──────────────┐      ┌─────────┴─────────────────────────────────────────┐
│ peakcore stats …     │      │ peakcore-ui.exe (Tauri + Vue)                     │
│ (подкоманды CLI      │      │  Rust-сторона: Sampler L2 (процессы, диск, сеть,  │
│  в том же exe)       │      │  GPU) пока окно видимо; клиент pipe для истории   │
└──────────────────────┘      │  Фронтенд: дашборд                                │
                              └───────────────────────────────────────────────────┘
```

### Двухуровневая выборка

- **L1 (демон, всегда):** `GetSystemTimes`, `GlobalMemoryStatusEx` / `GetPerformanceInfo`. Микросекунды на вызов.
- **L2 (процесс UI, только пока окно видимо):** один вызов `NtQuerySystemInformation(SystemProcessInformation)` даёт все процессы сразу: CPU-время, working set, private bytes, I/O-счётчики, потоки, handles. Плюс PDH для диска/сети/GPU.
- Окно **свёрнуто или скрыто → L2 останавливается**, графики не перерисовываются.

Формулы:
- CPU системы: `1 − Δidle / (Δkernel + Δuser)` (в `GetSystemTimes` kernel включает idle).
- CPU процесса: `Δ(kernel+user) / (Δwall × логических ядер)`.
- Память: «используется» = `total − available`; в рейтинге процессов по умолчанию **Private Bytes**, Working Set — отдельной колонкой.

### Устойчивость

- UI без демона работает автономно (история копится с момента запуска).
- Демон без UI работает полноценно (трей, алерты, CLI).
- Повторный запуск демона → mutex → просто показывает окно.
- Повторный запуск UI → single-instance → выводит существующее окно вперёд.

## 5. Модели данных (Rust, `peakcore-core`)

```rust
pub struct SysSnapshot {
    pub ts_ms: u64,
    pub cpu_total: f32,            // 0..100
    pub cpu_cores: Vec<f32>,       // по логическим ядрам (L2/по запросу)
    pub mem: MemInfo,
}

pub struct MemInfo {
    pub total: u64, pub used: u64, pub available: u64,   // байты
    pub cached: u64,
    pub commit_used: u64, pub commit_limit: u64,
    pub pagefile_used: u64, pub pagefile_total: u64,
}

pub struct ProcSample {
    pub pid: u32, pub ppid: u32,
    pub name: String, pub exe_path: Option<String>,
    pub cpu: f32,                  // % от всей машины
    pub private_bytes: u64, pub working_set: u64,
    pub io_read_bps: u64, pub io_write_bps: u64,
    pub threads: u32, pub handles: u32,
}

pub struct AppGroup {              // группировка по имени exe
    pub name: String, pub pids: Vec<u32>,
    pub cpu: f32, pub private_bytes: u64, pub working_set: u64,
    pub io_read_bps: u64, pub io_write_bps: u64,
}

pub struct HistoryPoint { pub ts_ms: u64, pub cpu: f32, pub mem_pct: f32 }
```

История: 1 ч × 1 точка / 2 с = 1800 точек (≈ десятки КБ). Для 24 ч — минутные агрегаты (avg, max): 1440 точек.

## 6. IPC-протокол (демон ↔ клиенты)

Транспорт: named pipe, доступ только текущему пользователю (DACL).
Кадры: `u32` длина (LE) + UTF-8 JSON. Версия протокола в каждом запросе.

Запросы:

```json
{"v":1,"op":"ping"}
{"v":1,"op":"snapshot"}
{"v":1,"op":"history","range":"1h"}          // "5m" | "15m" | "1h" | "24h"
{"v":1,"op":"show_window"}                   // демон запускает/выводит UI
{"v":1,"op":"shutdown"}
```

Ответ: `{"v":1,"ok":true,"data":{…}}` или `{"v":1,"ok":false,"error":"…"}`.

Правила: неизвестный `op` → ошибка, соединение не рвётся; таймаут чтения 2 с; максимальный размер кадра 1 МБ.

## 7. Метрики

### MVP

- CPU: общий %, по ядрам.
- Память: используется/всего/доступно, %, pagefile.
- Рейтинг процессов по CPU и по памяти; режим «по приложениям» (группировка) и «по процессам».
- История и графики.

### Расширения (по этапам)

| Метрика | Источник | Этап |
|---|---|---|
| Диск: busy %, чтение/запись МБ/с | PDH `PhysicalDisk` | M8 |
| Диск по процессам | `SystemProcessInformation` I/O | M8 |
| Сеть: вход/исход КБ/с по интерфейсам | `GetIfTable2` | M8 |
| Commit charge, кэш/standby | `GetPerformanceInfo` | M8 |
| Потоки/handles/число процессов | `SystemProcessInformation` | M8 |
| Детектор роста памяти процесса (утечки) | история топ-процессов | M9 |
| Алерты по порогам | демон | M9 |
| GPU: загрузка, VRAM | PDH «GPU Engine» (универсально), NVML опционально | M11 |
| Температуры | требует драйвер/права | вне плана |
| Сеть по процессам | ETW, админ-права | вне плана |

## 8. Иконка в трее

- Холст: размер по DPI (16 px при 100 %, 20/24 при 125–150 %, 32 при 200 %). Рисуем в RGBA, подаём в `tray-icon` (`Icon::from_rgba`).
- Раскладка: **две строки по два числа**, верх — CPU, низ — RAM.
- Шрифт: собственный пиксельный 3×5, цифра = 3 px, пробел 1 px; число из двух цифр = 7×5 px, две строки + зазор = 7×11 px. На 16×16 помещается, при больших DPI масштабируется целым множителем.
- Значение ≥ 100 показывается как `99`.

Битмапы цифр (`1` = пиксель):

```
0: 111 101 101 101 111      5: 111 100 111 001 111
1: 010 110 010 010 111      6: 111 100 111 101 111
2: 111 001 111 100 111      7: 111 001 001 010 010
3: 111 001 111 001 111      8: 111 101 111 101 111
4: 101 101 111 001 001      9: 111 101 111 001 111
```

- Цвет цифр по уровню: < 60 % зелёный, 60–85 % жёлтый, > 85 % красный; фон — тёмная полупрозрачная подложка для читаемости на светлом и тёмном трее.
- **Перерисовка только при смене цифр или уровня.**
- Tooltip: CPU %, RAM использовано/всего.
- Меню (правый клик): *Подробная статистика* (также левый/двойной клик), *Режим иконки* (CPU+RAM / только CPU / только RAM), *Период обновления* (1 / 2 / 5 с), *Запускать с Windows*, *Открыть конфиг*, *Выход*.
- Windows 11 может прятать иконку в overflow — описать в README, как закрепить.

## 9. Дизайн окна («дашборд»)

### Общий вид

Безрамочное окно (по умолчанию 1180×760, мин. 900×600), кастомная title bar, слева узкая навигация с иконками, сверху панель с выбором периода и поиском, справа основной контент в сетке карточек. Тёмная тема по умолчанию, светлая — по системной настройке или вручную. На Windows 11 фон с Mica.

### Страницы

- **Обзор** — как выше.
- **Процессы** — полная таблица: иконка приложения, имя, PID(ы), CPU % (с inline-полоской), память (private/working set), диск I/O, потоки. Переключатель «Приложения / Процессы», раскрывающиеся группы, сортировка по колонке, поиск, виртуализированные строки, закрепление топ-N.

### Анимации и производительность UI

- Все числа — плавный tween, графики — обновление без полной перерисовки.
- `prefers-reduced-motion` отключает анимации.
- `document.visibilityState !== 'visible'` или окно свёрнуто → остановить таймеры, анимации и подписки на данные (команда в Rust-сторону на остановку L2).
- Иконки приложений (из exe через `SHGetFileInfo`/`ExtractIconEx`) кэшируются в памяти как PNG и отдаются по запросу, не пересылаются каждым тиком.
- Данные во фронтенд идут пакетом раз в секунду (событие Tauri), а не по одной метрике.

### Доступность

Контраст текста не ниже WCAG AA, статус дублируется иконкой/текстом, полная навигация с клавиатуры, фокус-кольца, масштабирование по DPI.

## 10. Конфигурация, автозапуск, установка

`%APPDATA%\PeakCore\config.toml`:

```toml
[sampling]
tray_interval_ms = 2000
window_interval_ms = 1000

[tray]
mode = "cpu_ram"          # cpu_ram | cpu | ram
warn_pct = 60
crit_pct = 85

[history]
minutes_detail = 60
hours_aggregate = 24

[ui]
theme = "system"          # system | dark | light
language = "ru"           # ru | en

[[alerts]]
metric = "ram"
threshold_pct = 90
duration_s = 30
cooldown_min = 10
```

- Автозапуск: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` (без админа), запускает только демон.
- Установка: Tauri NSIS-установщик в режиме «для текущего пользователя» (без UAC); `peakcore.exe` кладётся в ту же папку. Дополнительно portable-zip.
- Логи: `%LOCALAPPDATA%\PeakCore\logs`, ротация, уровень `warn` по умолчанию.

Release-профиль демона:

```toml
[profile.release]
opt-level = "s"
lto = true
codegen-units = 1
panic = "abort"
strip = true
```

## 11. План разработки

Размер: S ≈ до дня, M ≈ 2–3 дня, L ≈ 4–6 дней (с учётом работы вместе с агентом). Каждый этап — отдельная ветка/PR; этап считается закрытым, когда выполнены все пункты «Критерии готовности».

### M0 — Подготовка (S)

**Задачи**
- [ ] Создать репозиторий, Cargo workspace с тремя крейтами (`core`, `sys`, `daemon`).
- [ ] `rustfmt`, `clippy -D warnings`, `rust-toolchain.toml`.
- [ ] CI (GitHub Actions, `windows-latest`): fmt, clippy, test, release-сборка, вывод размера exe.
- [ ] Скрипт `scripts/measure.ps1`: запускает exe, ждёт 60 с, печатает working set / private bytes / CPU.
- [ ] README с целями и бюджетом (раздел 1).

**Критерии готовности:** CI зелёный на пустом проекте; скрипт замера работает.

### M1 — Ядро и сэмплеры L1 (M)

**Задачи**
- [ ] Модели из раздела 5 в `peakcore-core`.
- [ ] `peakcore-sys`: `cpu_total()` на `GetSystemTimes` (с хранением предыдущих значений), `mem_info()` на `GlobalMemoryStatusEx` + `GetPerformanceInfo`.
- [ ] Кольцевой буфер истории фиксированного размера + минутные агрегаты.
- [ ] Unit-тесты: расчёт CPU по дельтам (на подставных значениях), ring buffer (переполнение, порядок), агрегаты.
- [ ] Консольный режим `peakcore --print` для отладки: печатает снимок раз в секунду.

**Критерии готовности:** значения CPU/RAM совпадают с Диспетчером задач (±2–3 п.п.); тесты зелёные; в простое консольная версия потребляет < 0.1 % CPU.

### M2 — Трей (M)

**Задачи**
- [ ] Win32 message loop + таймер на `tray_interval_ms`.
- [ ] Single-instance через именованный mutex.
- [ ] Рендер иконки: растровый шрифт 3×5, две строки, цвет по уровням, поддержка DPI.
- [ ] Обновление иконки только при смене цифр/уровня; tooltip.
- [ ] Меню (раздел 8), пока без окна: пункты «Подробная статистика» — заглушка.
- [ ] Автозапуск (реестр) — переключатель в меню.
- [ ] Snapshot-тест рендера иконки (сравнение с эталонными PNG для нескольких значений).
- [ ] Ручная проверка читаемости на DPI 100 % / 125 % / 150 % / 200 %, светлый и тёмный трей.

**Критерии готовности:** иконка читаема на всех проверенных DPI; повторный запуск не создаёт вторую иконку; бюджет демона соблюдён (замер `measure.ps1`: ≤ 8 МБ, < 0.1 % CPU).

### M3 — IPC и CLI (M)

**Задачи**
- [ ] Pipe-сервер в демоне (раздел 6), DACL только для текущего пользователя, отдельный поток.
- [ ] Клиент в `peakcore-core` (используется CLI и UI).
- [ ] Подкоманды в `peakcore.exe`: `stats`, `stats --json`, `history --minutes N --csv`.
- [ ] Валидация: лимит кадра, таймауты, неизвестный `op`.
- [ ] Интеграционные тесты: сервер + клиент в одном процессе.

**Критерии готовности:** `peakcore stats --json` отдаёт валидный JSON за < 50 мс; демон не падает на мусорных данных в pipe; без демона CLI печатает понятную ошибку.

### M4 — Сэмплер процессов L2 (L)

**Задачи**
- [ ] `peakcore-sys`: обёртка над `NtQuerySystemInformation(SystemProcessInformation)` с переиспользуемым буфером и перерасчётом при `STATUS_INFO_LENGTH_MISMATCH`.
- [ ] CPU процесса по дельтам времени; кэш предыдущих значений по PID (защита от переиспользования PID — сравнивать create time).
- [ ] Путь к exe (для иконок): `QueryFullProcessImageNameW` лениво и с кэшем, для недоступных процессов — без пути, без падений.
- [ ] Группировка в `AppGroup` по имени exe.
- [ ] Сортировка и top-N.
- [ ] Бенчмарк: время одного опроса на машине с 300+ процессами.
- [ ] Подкоманда `peakcore top --by cpu|mem -n 10` (разовый замер, через общий код).

**Критерии готовности:** топ процессов согласуется с Диспетчером задач; опрос < 15 мс на 300 процессов; нет утечек памяти при 10 000 опросах (проверка тестом).

### M5 — Каркас окна и дизайн-система (L)

**Задачи**
- [ ] `ui/`: Tauri v2 + Vue 3 + TS + Vite + Tailwind + Pinia.
- [ ] Безрамочное окно, `TitleBar`, перетаскивание, кнопки окна; Mica на Windows 11 (`window-vibrancy`), фолбэк на сплошной фон.
- [ ] Токены темы (раздел 9) как CSS-переменные, переключение тёмная/светлая/системная.
- [ ] Шрифты Inter и JetBrains Mono в комплекте (subset).
- [ ] Навигация (боковая панель), роутинг, пустые страницы-заглушки, `Skeleton`.
- [ ] Single-instance окна; запуск из демона по клику (`CreateProcess` рядом лежащего `peakcore-ui.exe`; если уже открыт — вывести вперёд).
- [ ] Окно изначально скрыто и показывается после первого кадра (без белой вспышки).
- [ ] Rust-сторона UI: подключение к pipe демона, L2-сэмплер в фоновом потоке, события во фронтенд раз в секунду; команды `start_sampling` / `stop_sampling`.
- [ ] Остановка L2 при сворачивании/скрытии окна.

**Критерии готовности:** клик по трею открывает окно за < 1 с без вспышек; закрытие окна завершает процесс UI полностью (проверить по Диспетчеру); свёрнутое окно ≈ 0 % CPU.

## 12. Тестирование

- **Unit:** расчёт CPU по дельтам, ring buffer, агрегаты, парсинг конфига, рендер иконки (snapshot).
- **Интеграционные:** pipe-сервер и клиент, CLI против живого демона.
- **Ручная матрица:** DPI, темы, Win10/11, много процессов, сон/пробуждение (после resume дельты не должны давать скачки и отрицательные значения).
- **Бюджет:** `scripts/measure.ps1` запускается перед закрытием каждого этапа, результат пишется в PR.
- **Визуальная проверка UI:** скриншоты обеих тем на каждой странице в PR.

## 13. Риски и открытые вопросы

1. **Читаемость иконки** на 16×16 — прототип сделать в M2 и показать до остальной работы; запасной вариант: одна метрика на иконке.
2. **Процессы без доступа:** без админа часть системных процессов покажет только имя; это нормально, пометить в UI.
3. **WebView2 на Windows 10:** нужен bootstrapper; без интернета при установке — вшитый fixed runtime (увеличит установщик).
4. **Mica и производительность** на старых машинах: фолбэк на сплошной фон по настройке.
5. **Ложные срабатывания антивирусов** на небольших exe с автозапуском и чтением процессов — подпись и аккуратный манифест.
6. **Что считать «потреблением памяти»:** по умолчанию Private Bytes, Working Set — рядом; зафиксировано в M4.
7. **Лицензия и распространение** (open source / закрытый): решить до M10.
